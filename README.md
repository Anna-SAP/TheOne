# THE ONE 爆款试听室

上传几首歌，应用从里面**只选一首**最有爆款潜质的，并用一位顶级制作人的口吻给出逐条理由。每条理由都落在这批歌自己的测量值上（时间点、dB、次数），并点名它胜过的是哪一首、差在哪里。

纯前端单页应用，没有后端，也没有构建步骤。音频只在浏览器里解码和分析，不会上传。

**在线试用：<https://anna-sap.github.io/TheOne/>**

## 运行

- 直接双击打开 `index.html`，或者
- `npm start`（等同于 `python3 -m http.server 8080`），然后打开 <http://localhost:8080>
- 线上版本由 `.github/workflows/pages.yml` 发布：每次 `main` 有新的合并，先跑测试，通过后自动更新 GitHub Pages

手边没有音频时，点「用 3 首合成示例试一下」，应用会现场合成三首结构不同的短歌并走完整个流程。

## 它听什么

每首歌解码后做一遍客观测量（`js/analysis.js`）：

| 测量 | 方法 |
| --- | --- |
| 响度、动态 | K 计权整合响度（近似 ITU-R BS.1770，带门限）、短时响度曲线、峰值响度比 |
| 速度、律动 | 频带谱通量起音包络 → 自相关 + 梳状评分，输出 BPM 和律动稳定度 |
| 调性 | 色度向量与 Krumhansl-Schmuckler 调性轮廓匹配，另算五声音阶占比 |
| Hook | 色度（和声）× 频带电平（配器）的自相似矩阵，找出全曲反复出现的片段；中间隔着别的素材才算一次新的「登场」 |
| 其他 | 频段能量分布、声场宽度、进入状态的时间、全曲最大的一次能量抬升 |

然后按九个维度打分并加权（`js/judge.js`）。前七项看整首歌，后两项看剪下来的短视频切片：

| 维度 | 权重 | 看的是 |
| --- | --- | --- |
| Hook 记忆点 | 20% | 整首歌里有没有一段会原样回来的东西，回来几次，占多少篇幅 |
| 爆点落差 | 14% | 进 hook 那一下抬了多少 dB，全曲有没有收放 |
| 黄金开场 | 12% | 整首歌里多快进入状态，多快亮出 hook |
| 律动 | 11% | 拍点稳定度、起音密度、速度 |
| 声音完成度 | 8% | 响度、动态余量、声场、高频 |
| 旋律调性 | 6% | 调性清晰度、五声占比 |
| 结构效率 | 6% | 时长、高潮位置 |
| 前奏切片 | 9% | 开头最好用的 5–10 秒，单独剪出来当短视频配乐的效果 |
| Hook 切片 | 14% | hook 段最好用的 5–10 秒，脱离整首歌单独成立的效果 |

### 短视频切片怎么评

同一首歌常要截 5–10 秒做成抖音、TikTok 的片段，所以每首歌会各挑两条切片：

- **前奏切片**取自开头 20 秒；如果第一次 hook 在这之前登场，就到 hook 为止。
- **Hook 切片**取自 hook 的每一次登场，选得分最高的那条；没有 hook 的歌取全曲最响的一段。
- 切片长度只取整小节（按测得的 BPM），起点只取重音位置，然后在候选里选总分最高的。

切片只按片段自己的五件事打分，各 0–100：

| 分项 | 占比 | 量的是 |
| --- | --- | --- |
| 起手 | 26% | 第一秒的响度相对整段、起点是否踩在重音上 |
| 卡点 | 22% | 片段内部的拍点清晰度和起音密度，画面能不能跟着切 |
| 循环接缝 | 20% | 播完跳回开头时，和声、配器、响度接不接得上 |
| 不塌 | 14% | 片段中间最轻的一秒掉了多少 dB |
| 手机外放 | 18% | 手机喇叭放得出来的频段（约 320 Hz–5 kHz）占多少能量 |

这五项都不用全曲结构信息，所以不会和已有维度重复计分：hook 回来几次、占多少篇幅归「Hook 记忆点」；要等多久才进入状态、才出现 hook 归「黄金开场」。

总分最高的就是 the one。判词由数据驱动生成：赢家的理由取「权重 × 领先幅度」最大的几个维度；每首落选的歌，说的是它相对赢家差距最大的那一项，如果它有某项比赢家强，也会先承认。

## 边界

这是一套基于音频特征的经验模型。它不听歌词，不认识歌手，也不能保证市场结果。调性检测可能把一首歌报成它的关系大小调；BPM 在很快或很慢的歌上可能报成半速或倍速。

## 目录

```
index.html      页面
styles.css      样式（明暗两套主题）
js/analysis.js  音频测量引擎（无 DOM 依赖）
js/judge.js     评分与判词
js/demo.js      示例歌曲合成器
js/sniff.js     解码失败时的文件诊断（加密缓存、DRM、不支持的编码、文件不完整）
js/app.js       界面：上传、进度、判决页、试听
test/           node --test 单元测试
```

## 测试

```bash
npm test
```

测试用合成歌曲做已知答案的校验：BPM、副歌入口时间、前奏长度、响度定义，以及判词是否点名对手、是否随输入变化。
